# なぜなぜ分析（agent 向け）

トヨタのなぜなぜ分析を、agent が崩さずに回せる形にしたもの。

## 決まり

| 決まり | やり方 |
|---|---|
| 現地・現物を見る | 各「なぜ」の答えに証拠（コード・ログ・データ・画面・git 履歴）を付ける。証拠の無い答えは「仮説」と書いて区別する |
| 枝分かれさせる | 原因が複数あれば 1 本の鎖にまとめない。枝ごとに掘る |
| 人のせいで止めない | 「agent が忘れた」「確認漏れ」「不注意」は原因ではない。なぜ仕組みがそれを許したかまで掘る |
| 止める点 | 直せば同じ症状が二度と出ない、自分たちが手を出せる原因。5 回は目安で、回数ではなくこの条件で止める |
| 逆から読む | 根本原因から症状へ「だから〜」でつないで読み、筋が通るか確かめる。通らなければ途中の「なぜ」が間違っている |
| 対策を分ける | 応急処置と恒久対策を別の TODO にする |

## Jev で点検する

書き終えたら、使う前に `bigdaddy:jev-gates` の `scripts/check-naze.sh` で各段を点検する。全段を 1 回の問い合わせで評価する（約 1 秒）。

- Jev が無効（`BIGDADDY_JEV=1` でない。`check-naze.sh` が exit 3）のときは、`check-naze.sh` の代わりに各段を自分で点検する。段ごとに、証拠が観測か推測か、前の段の原因になりうるか、人のせいで止めていないか、最後の段が直接変えられて再発を止めるかを確かめる。点検の記録には「Jev未使用：無効」と書く。
- `flags` に出た段を直してから使う。証拠が弱い段は証拠を取りに戻り、前の段とのつながりが弱い段は立て直し、人のせいにしている段はさらに掘る。
- 最後の段の `root_actionable` と `root_prevents` が両方 0.5 以上になるまで掘る。
- 掘るか止めるかを決めたら、`bigdaddy:logic-audit` の決定モードで点検する。
- `causes_prev` が低い段、または因果の飛躍が疑わしい段（時系列だけ・相関だけ・「〜なら〜」の逆向き）は、`bigdaddy:logic-audit` の決定モードで「この段を採るか」を点検し、`flags` が出たら本来の手順で精査する。代替説明・交絡・逆因果・後件肯定を確かめ、成り立たなければその段を「仮説」に格下げする。Jev の値は篩いで、段が成り立つかの判定は logic-audit の論証と反例で行う。
- 枝は `parent` に親の段番号を書く。枝を鎖として書くと、つながりの評価が下がる（下の例の なぜ5 は、鎖として書くと 0.24〜0.5、なぜ2 の枝として書くと 0.79）。

## 書き方

```markdown
| | なぜ | 答え | 証拠 |
|---|---|---|---|
| 症状 | — | <観察した症状> | <どこで見たか> |
| なぜ1 | なぜ <症状>？ | <答え> | <証拠 or 仮説> |
| なぜ2a | なぜ <答え1>？ | ... | ... |
| なぜ2b（枝） | ... | ... | ... |

逆から読む: <根本原因> だから <…> だから <症状>。
応急処置: <…>
恒久対策: <…>
未確認: <仮説のまま残っている「なぜ」と、確かめる方法>
```

## 例: Check Backlog link の CI 失敗が繰り返された（2026-10）

| | なぜ | 答え | 証拠 |
|---|---|---|---|
| 症状 | — | CI「Check Backlog link」が落ちる | 3 セッションで同じ失敗 |
| なぜ1 | なぜ落ちる？ | PR 本文の `## Backlog` に Notion URL が無い | CI の検査内容 |
| なぜ2 | なぜ URL が無い？ | Notion の行を作らずに PR を作った | 同上 |
| なぜ3 | なぜ作らなかった？ | agent が「Notion は使えない」と判断した | 利用者が「Notion 繋がってるよ」と 3 回訂正 |
| なぜ4a | なぜそう判断した？ | Notion のツールは起動時に読み込まれず、ToolSearch で探さないと見えない | 仮説（別セッションでの観察） |
| なぜ4b（枝） | 本当に使えないこともある？ | 認証が切れていることがある | 別セッションで「要認証」と表示 |
| なぜ5（なぜ2 の枝） | なぜ URL の無い PR を作れてしまった？ | 起票が PR 作成の最後の段にあり、文章のルールでしか決まっていない | CLAUDE.md、PR 前のゲートが無い |

逆から読む: 起票が最後の段で文章でしか決まっていない だから 見つけられないと黙って飛ばす だから URL の無い PR ができる だから CI が落ちる。

- 応急処置: CLAUDE.md に「Notion は ToolSearch で探せ」と書く（弱い）。
- 恒久対策: 起票を前段の TODO 作成時に移す。PR 作成前のゲートを置く。認証切れは人に返す。
- 未確認: なぜ3〜4a は推論。失敗したセッションの記録を読んで確かめる。
